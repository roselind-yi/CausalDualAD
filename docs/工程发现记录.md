## 一、代码缺陷

### ✅ F-001：异常分数被窗口均值稀释（已修，效果显著）

**位置**：`src/ucr_pipeline/trainer.py` → `detect_anomalies()`

**原问题**：分数分配时取整个窗口的平均值：
```python
window_score = float(np.mean(fused_np[i]))   # 一个 64 点窗口取均值
```

**后果量化**：

| 窗口内异常点数 | 占窗口比例 | 分数被稀释到 |
|---|---|---|
| 5 / 64 | 7.8% | 0.078 倍 |
| 1 / 64 | 1.6% | 0.016 倍 |

**各指标受影响程度**：

| 指标 | 是否受影响 | 原因 |
|---|---|---|
| AUROC / VUS-ROC | 轻微 | 看全局排序，稀释是线性缩放，不改变窗口间相对顺序 |
| Top-k | 轻微 | 同上 |
| **VUS-PR / F1** | **严重** | 依赖分数绝对量级，稀疏异常被稀释到接近正常水平 |
| 跨数据集比较 | **严重** | 各数据集异常稀疏度不同 → 稀释程度不同 → 分数不可横向比较 |

**修复**（2026-10-13）：
- 池化方式参数化为 `pool`: `max`（新默认）/ `mean`（旧行为）/ `topk_mean`
- 分配方式参数化为 `assign_mode`: `full`（新默认，覆盖整个窗口）/ `center`（旧行为）
- `max` 池化保留稀疏异常，不被正常点稀释
- `full` 分配消除首尾未覆盖点

**修复效果（SMAP，同一模型同一超参）**：

| 配置 | AUROC | VUS-PR | 未覆盖点 |
|---|---|---|---|
| `pool=mean, assign=center`（旧） | 0.4790 | 0.0096 | 43 点 |
| `pool=max, assign=full`（新） | **0.8035** | 0.0249 | **0 点** |

**AUROC 提升 0.32**，且"SMAP 低于随机"这个结论被推翻 —— 之前看到的 0.4276 是稀释伪影。

**这个结果同时说明**：之前那组"跨数据集 AUROC 跨度 0.57"的普查数据**大部分是池化伪影**，
不能作为论文结论，必须用修复后的配置重跑。

### ✅ F-002：数据末尾 43 个点永远得不到真实分数（已修）

**位置**：同 F-001

**原问题**：窗口 `s` 只把分数分配给 `[s + W//3, s + 2W//3)`，即窗口中间 1/3。

**原未覆盖比例**：

| 数据长度 | 窗口 | 未覆盖点数 | 占比 |
|---|---|---|---|
| 100 | 64 | 43 | **43%** |
| 200 | 64 | 43 | 21.5% |
| 1000 | 64 | 43 | 4.3% |
| 8000 | 64 | 43 | 0.5% |

**修复**：`assign_mode=full` 把分数分配给整个窗口 `[s, s+W)`，靠 count 归一化处理重叠，
未覆盖点归零。`detect_anomalies` 现在会在日志中打印未覆盖点数（应为 0）。

**顺带修了一个隐藏 bug**：原代码用 `count > 1.0` 判断"已覆盖"，但单个窗口覆盖的点 count 也是 1.0，
判断逻辑错误。现改为记录 `count == 0` 的掩码，在 `count` 被置 1 之前保存。

### 🟠 F-005：`detect_anomalies` 的 for 循环分配是性能瓶颈

当前实现仍保留 Python for 循环遍历窗口做分数分配：
```python
for i, ws in enumerate(window_starts):
    score_sum[cs:ce] += pooled[i]
    count[cs:ce] += 1.0
```

8000 点/窗口 64 时约 7900 次循环，实测检测耗时 8.6 秒（927 窗口/秒）。

**可用 `np.add.at` 或差分前缀和优化**，但当前 CPU 下检测不是主要瓶颈（训练才是），
暂不处理。若换GPU 后训练变快，这个会成为瓶颈。

### 🟡 F-003：`MultiScalePrototypeMatchingPath` 曾把通道维吃掉（已修）

**问题**：旧实现把输入最后一维当 `feature_dim`：
```python
lead_shape = x.shape[:-1]
return total_score.reshape(*lead_shape)     # (B,W,C) -> (B,W)，通道维丢失
```

导致多变量下两条路径分数维度不一致，**此前文档里写的"原型匹配作用在重构误差上"实际没生效**。

**修正**（提交 `f779e21`）：原型参数 `(P, C)` → `(C, P)`，每通道一套原型，
`(B,W,C)` 进 `(B,W,C)` 出。

**死代码已清理**：`model._prototype_per_channel()` 无任何调用，已删除。

---

### 🟡 F-004：L1 距离替代欧氏距离，未做论证

`model.py` 原型匹配用 `torch.cdist(..., p=2.0)`（欧氏），重写后用 L1。

**理由**：L1 对单个维度的离群更鲁棒，且便于逐通道计算（避免 (N,C,P) 的欧氏广播开销）。

**待补**：应做一次 L1 vs L2 的消融，否则审稿人会问"为什么用 L1"。

## 二、数据问题

### 🔴 D-001：训练集截取严重破坏分布多样性（影响 SMD 的 0.9966）

**问题**：为控制 CPU 耗时，实验统一用 `--max-points 8000 --start-offset 3000`，
即只取训练集 `[3000, 11000)` 这一段。

**实测截取段 std 与全量 std 的比值**：

| 数据集 | 全量 std | 截取段 std | 比例 |
|---|---|---|---|
| SMAP | 0.1097 | 0.1088 | **0.99** ✅ 分布完整 |
| MSL | 0.0493 | 0.0518 | **1.05** ✅ 分布完整 |
| **SMD** | 0.1393 | 0.0499 | **0.36** ❌ 只剩三分之一 |

**SMD 的问题**：训练时模型只见过序列开头一小段（方差小、模式单一），
而测试段 `[3000, 11000)` 的分布明显不同。
模型在"见过的简单分布"上表现好，一旦遇到复杂模式就崩 —— **这恰恰就是分布偏移**，
但我们把它当成了泛化能力强的证据。

**结论**：**SMD 的 AUROC 0.9966 高度可疑，不能作为可信结果引用。**

**修正方案**：
1. 正式实验必须用**全量训练集**（SMD 70 万点在 CPU 上约需数小时，需找 GPU）
2. 截取实验只能用于**趋势探索**，结果要显式标注"训练集截取至X 点"
3. 若必须截取，按**分层采样**而非连续切片，保证覆盖多种运行状态

**状态**：待修（正式实验前必须处理）

## 三、方法层面的发现

### 🟢 M-001：聚合策略对性能的影响与通道数正相关（⚠️ 基于旧池化配置，需重做）

**实验**：统一配置（8000 点 / 窗口 64 / 5 epoch / batch 128）下比较三种通道聚合

| 数据集 | C | max | mean | topk_mean |
|---|---|---|---|---|
| MSL | 55 | 0.4879 | **0.6135** (+0.13) | 0.4921 |
| SMAP | 25 | 0.4276 | **0.4695** (+0.04) | 0.3924 |

**三个发现**：
1. **mean 系统性优于 max** — 验证"max 放大单通道噪声"假设
2. **提升幅度与通道数正相关** — 55 通道 +0.13，25 通道 +0.04
3. **topk_mean 反而最差** — 聚合策略不是连续谱，"折中"设计两头不沾

**⚠️ 重要提醒**：这组实验是在**旧的 mean池化 + center 分配**下做的，
F-001 修复后 SMAP AUROC 从 0.4790 → 0.8035，说明池化影响远大于聚合策略。
**这组消融必须在修复后的配置下重做**，现有结论不可信。

**论文价值（方向不变）**：「聚合方式 × 通道数 对异常检测性能的影响」
正是调研中指出的**评测空白**（LEFT, KDD'26 批评"多数跨视图方法只做分数融合，
不分析聚合策略"）。

---

### ✅ M-002：SMAP 换 mean 后仍低于随机 → 是池化伪影，不是聚合问题

**原结论**：SMAP 三种聚合全部 < 0.5，误判为"聚合不是主因，存在更深层原因"。

**修复后真相**：F-001 修复后，SMAP 用 max 聚合 + max 池化得到 **AUROC 0.8035**。
问题出在**窗口池化**，不是通道聚合，也不是什么"更深层原因"。

**教训**：跨层级的实验设计要正交——通道聚合、窗口池化、分数分配是三个独立维度，
之前只在一个维度上做消融，结论自然片面。

## 六、实验配置的三个正交维度（2026-10-13 新增）

之前只在一个维度上做消融，导致结论片面。现在明确三个维度**必须正交**：

| 维度 | 参数 | 取值 | 默认 |
|---|---|---|---|
| **通道聚合** | `aggregate` | max / mean / topk_mean | max |
| **窗口池化** | `pool` | max / mean / topk_mean | max |
| **分数分配** | `assign_mode` | full / center | full |

- 通道聚合：`(B,W,C)` → `(B,W)`，多变量时如何合并各通道分数
- 窗口池化：`(B,W)` → 标量，一个窗口的分数如何代表该窗口
- 分数分配：标量 → 时间点序列，覆盖整个窗口还是只覆盖中间

**F-001 就是因为只调了通道聚合、没管窗口池化，导致误判。**
完整消融需要 3 × 3 = 9 组组合（对关键数据集）。
